# Спецификация и архитектура проекта WhisperKey (v3.0 UI-First & Multi-call Binary)

### 1. Концепция продукта

Нативная, монолитная утилита для голосового ввода текста в macOS с абсолютным нулем задержек. Вся система поставляется в виде одного бинарного файла. Тяжелая инициализация (загрузка 1.5 ГБ модели, открытие аудиоустройств) происходит один раз при старте. В момент диктовки не происходит ни выделения памяти (`malloc`), ни порождения новых процессов (`fork`).

### 2. Технический стек

* **Язык:** Чистый C / Objective-C Runtime.
* **Структура:** Multi-call binary (поведение зависит от аргументов запуска).
* **Сборка:** `Makefile` с таргетами `debug` и `release` (один выходной файл `WhisperKey`).
* **Аудио:** `CoreAudio` (перманентный стриминг в кольцевой буфер с лимитом времени для защиты от переполнения).
* **Связь (IPC):** Однонаправленный анонимный пайп (`pipe`) от дочернего процесса (Движок) к родительскому (Интерфейс).
* **Вставка текста:** `NSPasteboard` + эмуляция `Cmd+V` через `CGEvent`.
* **Модель:** `ggml-medium.bin` (Multilingual), язык по умолчанию — `auto`.

---

### 3. Архитектура системы

Приложение компилируется в один файл, который имеет единую точку входа (`main.c`), разделяющую логику.
При запуске без аргументов стартует **Родительский процесс (UI)**, который сам форкает и запускает **Дочерний процесс (Engine)**.

#### 3.1. Родительский процесс (Интерфейс / `hud.m`)

Главный процесс приложения. Отвечает за взаимодействие с оконной подсистемой macOS и перехват системных разрешений TCC.

* **Инициализация:**
* Создает пайп для связи.
* Делает `fork() + exec("WhisperKey --engine <fd>")` для запуска движка в фоне.
* Настраивает асинхронное чтение из пайпа через Grand Central Dispatch (GCD), чтобы не блокировать Main RunLoop.


* **Поведение:**
* Парсит входящие строки из пайпа:
* `show_mic` -> Показывает безрамочное `NSWindow` у курсора с 🎙️.
* `show_wait` -> Меняет иконку на ⏳.
* `hide` -> Делает окно невидимым.




* **Защита от зомби:** Если дочерний процесс (Движок) умирает, пайп закрывается (EOF), интерфейс делает `exit(0)`. Если умирает Интерфейс, макось автоматически прибивает дочерний Движок (или он завершается по разрыву пайпа).

#### 3.2. Дочерний процесс (Оркестратор / `engine.c`)

Тяжелый демон, который выполняет всю черновую работу.

* **Инициализация (Boot):**
* Загружает модель: `whisper_init_from_file()` (занимает ~1.5 ГБ RAM).
* Поднимает `CoreAudio` и блокирует поток записи мьютексом (пауза).
* Вешает глобальный Carbon-хук на горячую клавишу.


* **Потоки (pthreads):**
1. **Main:** Ловит Carbon-события.
2. **Audio Stream:** Ждет сигнала, пишет сэмплы в кольцевой буфер.
3. **Watchdog:** Спящий поток. Раз в минуту проверяет атомарную переменную `last_used_timestamp`. Если простой > 10 минут, делает `whisper_free(ctx)`.



---

### 4. Жизненный цикл (Hot Path)

1. **Start (Хоткей нажат):**
* **Проверка памяти:** `engine` проверяет `if (ctx == NULL)`.
* *Если выгружена (Watchdog сработал):* шлет `show_wait` в UI, синхронно загружает модель в RAM с диска, затем шлет `show_mic`.
* *Если загружена:* задержка 0 мс, сразу шлет `show_mic`.


* **Аудио:** `engine` разблокирует аудио-поток (`pthread_cond_signal`). Данные льются в буфер.
* **Таймер:** Обновляется `last_used_timestamp`.


2. **Stop (Хоткей отпущен):**
* `engine` блокирует аудио-поток.
* Шлет `show_wait` в UI.
* Вызывает `whisper_full()`. Данные перевариваются (язык определяется автоматически).


3. **Done (Текст готов):**
* `engine` забирает текст из сегментов Whisper.
* Очищает `NSPasteboard` и записывает туда результат.
* Шлет `hide` в UI.
* Эмулирует нажатие `Cmd+V` (через `CGEvent`).
* Модель остается в памяти, система ждет следующего нажатия.



---

### 5. Нефункциональные требования (NFR)

* **Лимит буфера и VAD:** Кольцевой аудио-буфер жестко ограничен (например, 2 минутами) для защиты от `Buffer Overflow`. Перед отправкой в Whisper хвост буфера очищается от явной тишины (trim silence), чтобы избежать «галлюцинаций» нейросети.
* **Макросы логирования:**
* Отладочные макросы (`LOG_DEBUG`, `LOG_INFO`) для вывода размеров буфера, времени детекции и состояний Watchdog.
* `LOG_ERROR` для критических сбоев.


* **Конфигурации `Makefile`:**
* `make debug`: `-O0 -g -DDEBUG`. Логи включены, символы оставлены для отладки (`lldb`).
* `make release`: `-O3 -flto -DNDEBUG`. Максимальная оптимизация, логи вырезаны препроцессором, `strip` бинарника.



### 6. Системные права (TCC)

Поскольку главным запускаемым процессом теперь является UI-родитель, macOS корректно связывает все системные запросы с одним и тем же приложением `WhisperKey`.
При первом использовании система запросит:

1. **Microphone (Микрофон):** Для инициализации `CoreAudio` (запрашивает дочерний процесс, но окно атрибутируется родителю).
2. **Input Monitoring / Accessibility:** Для установки Carbon-хука и эмуляции `Cmd+V`.
